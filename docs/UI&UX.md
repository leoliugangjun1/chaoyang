# 服装视觉设计分析智能体视觉设计系统

## 1. 文档定位

本文档根据提供的视觉参考图，提炼适用于「服装视觉设计分析智能体」的桌面端设计系统。

适用范围：

- 第一页「产品需求输入」；
- 第二页「规则校验与设计调研」；
- 第三页「视觉看板」；
- 图片候选确认弹窗；
- 导出前视觉看板预览。

参考图中的品牌名称、文案、人物和花卉图片不作为产品素材，不直接复制。

## 2. 整体气质

### 2.1 核心气质

产品整体应呈现以下感受：

- 创意工作台，而不是传统数据后台；
- 高级但不疏离；
- 轻盈、明亮、具有视觉呼吸感；
- AI 辅助创作，而不是机器替代设计判断；
- 信息密度可控，重点内容突出；
- 视觉研究与业务分析并存；
- 有编辑杂志的审美，但保留工具的明确操作性。

### 2.2 气质关键词

```text
Creative / Editorial / Soft / Intelligent / Calm / Visual / Structured
```

中文对应：

```text
创意、编辑感、柔和、智能、克制、视觉化、结构清晰
```

### 2.3 视觉参考图的可迁移特征

- 大面积留白；
- 黑色高对比标题；
- 无衬线字体和少量衬线斜体形成对比；
- 大面积真实摄影作为视觉入口；
- 半透明深色内容面板叠加在图片上；
- 圆角图片和面板；
- 顶部导航轻量化；
- 内容以视觉叙事和短句为主，而不是长篇说明。

## 3. 设计方向

### 3.1 页面不是营销落地页

参考图具有品牌落地页特征，但本产品是设计工作台。迁移到 SaaS 后应保留视觉表达，同时增加：

- 当前项目状态；
- 阶段导航；
- 文件来源；
- 规则选择；
- 权重调整；
- 图片确认；
- 任务进度；
- 版本切换；
- 导出操作。

不得将业务功能隐藏在视觉装饰之后。

### 3.2 视觉优先，操作明确

主要内容区域可以具有杂志感，但每一个关键动作都必须有明确位置：

- 上传文件；
- 选择规则；
- 启动阶段；
- 确认产品事实；
- 应用权重；
- 选择图片；
- 导出 PDF。

## 4. 色彩系统

整体采用「暖白背景 + 黑色文字 + 蓝色和暖黄色摄影内容」的中性基础。

### 4.1 基础色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--color-canvas` | `#F5F5F3` | 页面主背景 |
| `--color-surface` | `#FFFFFF` | 普通内容区域 |
| `--color-ink` | `#111111` | 主标题、主要文字 |
| `--color-muted` | `#777777` | 辅助文字 |
| `--color-line` | `#E5E5E1` | 分隔线和边界 |
| `--color-black-panel` | `#1D1D1B` | 深色信息面板 |
| `--color-panel-text` | `#F7F7F3` | 深色面板文字 |

### 4.2 状态色

| 状态 | 色值 | 用途 |
| --- | --- | --- |
| 已确认 | `#2F6B57` | 事实确认、图片采用、阶段完成 |
| 处理中 | `#557D98` | 任务运行、联网获取、等待结果 |
| 待确认 | `#B28745` | 产品事实、图片候选、用户操作 |
| 数据不足 | `#A76B55` | 无法访问、缺少来源、资料不完整 |
| 失败 | `#A14E4E` | 阶段执行失败、规则执行失败 |
| 已停用 | `#9A9A94` | 历史规则、旧版本 |

状态色只用于标签、图标、边框和提示，不作为大面积背景色。

### 4.3 摄影辅助色

摄影图片可以引入低饱和蓝、奶油黄、浅粉和植物绿，但这些颜色只来自图片或局部视觉参考，不作为整个界面的主色系统。

推荐辅助色：

- 雾蓝：`#AFC6D3`；
- 暖奶油：`#EBD5B0`；
- 淡粉：`#E6B5B0`；
- 灰绿：`#A7B49F`。

### 4.4 使用比例

建议页面颜色比例：

- 暖白和白色：`70% - 80%`；
- 黑色和深灰文字：`10% - 15%`；
- 线条和中性灰：`5% - 10%`；
- 状态色和辅助色：不超过 `10%`；
- 大面积彩色来自真实图片，不使用装饰性渐变铺满页面。

## 5. 字体系统

### 5.1 中文字体

优先使用：

- `Noto Sans SC`；
- `PingFang SC`；
- `Microsoft YaHei`。

### 5.2 英文和数字

优先使用：

- `Inter`；
- `Helvetica Neue`；
- `Arial`。

### 5.3 编辑感标题

可以在视觉看板的主标题或重点短语中使用少量衬线斜体，形成参考图中的编辑感。

建议：

- 中文正文不使用衬线斜体；
- 不超过标题文本的 `30%`；
- 不用于按钮、表格、状态标签和错误提示；
- 仅用于视觉策划标题或重点概念。

### 5.4 字号层级

| 层级 | 桌面端建议字号 | 用途 |
| --- | --- | --- |
| 页面标题 | `36px - 56px` | 第三页视觉看板主标题 |
| 阶段标题 | `24px - 32px` | 页面和分析模块标题 |
| 模块标题 | `18px - 24px` | 产品事实、调研和策划模块 |
| 正文 | `14px - 16px` | 普通内容 |
| 辅助信息 | `12px - 13px` | 来源、采集时间、状态 |

页面输入、规则和表格区域不使用英雄级标题。大字号仅用于第三页的视觉看板标题。

## 6. 页面布局

### 6.1 全局框架

```text
┌──────────────────────────────────────────────────────┐
│ 品牌/项目名称     阶段导航        版本  导出/项目菜单 │
├──────────────────────────────────────────────────────┤
│                                                      │
│                  当前页面主内容                      │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 6.2 顶部导航

顶部导航保持轻量：

- 左侧：产品标识和当前项目名称；
- 中间：三个阶段导航；
- 右侧：版本选择、任务状态、导出入口；
- 不使用厚重侧边栏占据主要宽度；
- 当前阶段使用黑色文字和短底线或细边框提示。

### 6.3 第一页布局

第一页是总控制台，输入区域占主要空间。

```text
┌──────────────┬──────────────────────────────────────┐
│ 项目与版本   │ 产品资料上传区                       │
│ 当前规则     │ Markdown / Excel / 图片              │
│ 任务状态     │                                      │
│              ├──────────────────────────────────────┤
│              │ 校验 / 图片搜索 / 视觉策划规则选择    │
└──────────────┴──────────────────────────────────────┘
```

左侧是项目控制信息，右侧是主要输入区域。上传区域应支持拖拽，但不能只依赖拖拽，必须保留明显的文件选择按钮。

### 6.4 第二页布局

第二页采用「状态区 + 内容区 + 图片确认弹窗」结构：

```text
┌──────────────────────────────────────────────────────┐
│ 阶段状态 / 进度 / Markdown 8 / 联网 2                │
├──────────────┬───────────────────────────────────────┤
│ 内容导航     │ 产品事实 / 卖点证据 / 设计调研         │
│              │ 来源切换和内容详情                     │
├──────────────┴───────────────────────────────────────┤
│ 图片候选摘要                 [确认视觉参考图片]       │
└──────────────────────────────────────────────────────┘
```

图片候选不直接占据主页面大面积区域，采用弹窗集中确认。

### 6.5 第三页布局

第三页允许更强的视觉表达：

- 大面积留白；
- 视觉策划主标题；
- 真实图片或用户确认的视觉参考图；
- 深色内容面板叠加在图片上；
- 模块之间使用明显的节奏变化；
- 文字量控制在可扫读范围。

第三页仍然是可交互网页看板，不是自由画布。

## 7. 卡片风格

### 7.1 普通信息卡片

用于产品事实、卖点证据、调研结果和任务状态。

- 背景：白色或暖白；
- 边框：`1px solid #E5E5E1`；
- 圆角：`8px`；
- 阴影：默认无阴影；
- 内边距：`16px - 24px`；
- 标题和状态信息左对齐；
- 卡片之间使用间距，不使用多层嵌套。

### 7.2 深色视觉卡片

用于第三页视觉策划中的重点内容或图片叠加说明。

- 背景：`#1D1D1B`，透明度可为 `88% - 94%`；
- 文字：`#F7F7F3`；
- 边框：低对比度半透明白线；
- 圆角：`12px - 16px`；
- 可以使用轻微背景模糊；
- 不能把所有模块都做成深色卡片。

### 7.3 图片卡片

- 图片比例固定，避免加载前后布局跳动；
- 使用 `object-fit: cover` 展示场景图；
- 细节图使用 `object-fit: contain`；
- 图片下方显示简短说明和来源状态；
- 图片点击打开大图，不在卡片内堆叠大量文字。

### 7.4 禁止卡片套卡片

页面区块使用开放布局。卡片只用于：

- 重复信息项；
- 单条卖点；
- 单个图片候选；
- 单个证据；
- 弹窗中的确认对象。

不要把整个页面做成一个大卡片，再在里面放卡片。

## 8. 交互状态

### 8.1 文件上传

状态包括：

- 初始：显示上传入口和支持格式；
- 拖入：边框变为黑色，显示可放置提示；
- 解析中：显示文件名和进度；
- 已完成：显示文件类型、大小和删除入口；
- 解析失败：显示原因和重新选择入口；
- Excel 转换完成：显示原始 Excel 和转换后的 Markdown。

### 8.2 任务进度

状态包括：

- 未启动：显示启动按钮；
- 排队中：显示等待状态；
- 处理中：显示阶段、步骤和进度条；
- 数据不足：允许继续，同时列出缺失来源；
- 已完成：显示结果入口；
- 失败：显示原因和系统自动重新执行状态；
- 已取消：显示任务已取消，不展示本次运行中的中间结果。

### 8.3 产品事实确认

- 待确认：使用暖黄色标签；
- 编辑中：显示字段焦点和保存状态；
- 已修改未保存：显示未保存提示；
- 已确认：使用绿色状态；
- 字段缺失：显示字段级提示，不阻塞其他可处理内容；
- 关键字段缺失：阻止进入下一阶段，并说明缺失字段。

### 8.4 权重编辑

显示：

```text
Markdown 资料权重  8
联网检索权重        2
```

交互规则：

- 两个值总和固定为 `10`；
- 支持数字输入和步进调整；
- 修改后不立即执行完整分析；
- 点击「应用权重」后重新计算；
- 显示排序、证据强度和图片推荐的变化；
- 保存当前项目版本的最终权重。

### 8.5 图片确认弹窗

弹窗状态包括：

- 候选列表；
- 图片大图预览；
- 采用；
- 弃用；
- 待定；
- 批量操作；
- 来源打开失败；
- 用户补充截图；
- 已完成确认。

弹窗关闭后，第二页只显示汇总状态，不丢失用户选择。

### 8.6 导出前编辑

- 编辑中：显示当前修改状态；
- 已保存：显示保存时间；
- 未保存：离开页面前提示；
- 导出中：禁用重复导出；
- 导出完成：提供 PDF 查看入口；
- 导出失败：显示原因，不丢失看板编辑结果。

## 9. 动态模块

以下模块只在 SaaS 网页中显示：

- 来源链接；
- 采集时间；
- 事实/推断/假设/设计建议标签；
- 数据不足提示；
- 当前版本；
- 当前规则版本；
- Markdown/联网权重；
- 任务进度和错误状态。

这些模块不进入 PDF 正式内容。

## 10. 图片使用规则

### 10.1 图片角色

图片分为：

- 产品输入图片；
- 竞品证据截图；
- 行业视觉参考；
- 场景搭配参考；
- 用户内容参考；
- 用户确认后进入视觉策划的图片。

### 10.2 视觉处理

- 优先展示清晰、真实、可识别主体的图片；
- 不使用过度模糊、过度裁切或无法判断内容的图片；
- 图片叠加文字时保证对比度；
- 不用图片作为唯一信息载体；
- 图片必须有固定比例容器；
- 图片加载失败时显示占位和来源状态。

## 11. 需要避免的问题

### 11.1 视觉层面

- 避免大面积渐变背景；
- 避免紫色或蓝紫色主导整个页面；
- 避免装饰性光晕、漂浮圆球和无意义动效；
- 避免过度玻璃拟态导致文字不清晰；
- 避免所有模块使用同一种深色卡片；
- 避免标题过大挤压实际业务内容；
- 避免使用与服装品类无关的图片。

### 11.2 信息层面

- 避免把 Markdown、联网资料和推断混成一个无来源结论；
- 避免只展示结论而隐藏证据入口；
- 避免数据不足时用猜测填补；
- 避免用户无法判断当前使用的是哪个版本；
- 避免把技术状态提示带入 PDF；
- 避免未确认图片直接进入视觉策划。

### 11.3 交互层面

- 避免把关键操作藏在悬停菜单中；
- 避免每次输入权重都触发完整分析；
- 避免取消任务后继续显示旧的运行中间结果；
- 避免弹窗无法关闭或关闭后丢失选择；
- 避免长文本撑破卡片；
- 避免移动端和窄屏下按钮、标签和表格互相遮挡。

## 12. 动效建议

动效应服务于状态反馈，不用于装饰。

推荐：

- 页面切换使用 `160ms - 220ms` 淡入；
- 图片弹窗使用轻微缩放和淡入；
- 进度条使用平滑变化；
- 保存状态使用短暂提示；
- 卡片悬停只改变边框或阴影，不改变布局。

避免：

- 自动播放大面积背景视频；
- 无限循环动效；
- 影响文字阅读的图片缩放；
- 复杂视差和长时间转场。

## 13. Vibe Coding 实现要求

实现 Agent 必须先建立设计 Token，再实现组件。

推荐顺序：

1. 定义颜色、字号、间距和圆角 Token；
2. 实现全局导航和三阶段状态；
3. 实现普通信息卡、图片卡和深色视觉卡；
4. 实现上传、进度、确认和错误状态；
5. 实现图片确认弹窗；
6. 实现第三页视觉看板；
7. 实现导出前编辑和 PDF；
8. 使用真实长文本和多图测试布局稳定性。

实现时不要直接复制参考图的 HTML、品牌文案或图片，应只提炼视觉规则。

## 14. 验收标准

- 第一、二、三页视觉语言统一；
- 第一页和第二页保持工具效率，第三页允许更强视觉表达；
- 暖白背景、黑色文字和真实图片构成主视觉；
- 普通卡片圆角不超过 `8px`，视觉卡片可使用 `12px - 16px`；
- 视觉看板支持图片、文本、状态和来源的结构化展示；
- 所有任务状态都有明确视觉反馈；
- 数据不足、失败、取消和待确认状态可区分；
- 页面不出现文本重叠、图片溢出和布局跳动；
- PDF 不包含 SaaS 动态辅助信息；
- 参考图中的品牌和素材未被直接复制。
