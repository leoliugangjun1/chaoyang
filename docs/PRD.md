# 服装视觉设计分析智能体 PRD

## 1. 文档定位

本文档定义服装视觉设计分析智能体的产品目标、用户问题、核心使用流程、第一版功能边界和验收标准。

第一版以「美国市场、Amazon、女款亚麻混纺长裤」作为验证场景，但产品必须支持不同服装品类、国家、平台和视觉策划规则。

## 2. 产品定位

### 2.1 产品定位

这是一个面向服装设计和产品开发团队的 AI 视觉研究工作台，用于将产品资料、竞品资料、市场调研和视觉参考图片整理为可确认、可追溯、可导出的视觉策划看板。

### 2.2 核心价值

- 将分散的产品资料整理为可确认的产品事实；
- 将市场和竞品资料转化为有来源的设计调研；
- 将设计经验转化为可复用的视觉策略规则；
- 减少人工整理、重复搜索和跨文件排查；
- 保留每个结论的来源、版本和用户确认记录；
- 输出网页看板和 PDF，支持后续设计执行。

### 2.3 目标用户

- 服装产品经理；
- 服装视觉设计师；
- Amazon 运营和产品开发人员；
- 竞品研究人员；
- 负责制定视觉规则的资深设计人员。

## 3. 用户痛点

### 3.1 产品理解痛点

- 产品资料分散在 Markdown、Excel、图片和其他文件中；
- 设计人员需要人工整理产品背景；
- AI 可能把推断当成事实，导致视觉方案偏离产品；
- 核心卖点、目标人群、场景和用户利益没有统一结构。

### 3.2 市场调研痛点

- 竞品、用户需求、关键词和市场趋势需要分别搜索；
- 公开网页访问不稳定，数据和截图难以保存；
- Markdown 原始资料和联网补充资料容易混在一起；
- 视觉结论缺少来源、采集时间和证据关联。

### 3.3 视觉策划痛点

- 视觉方向依赖少数资深设计人员的经验；
- 不同设计人员对卖点顺序和视觉表达的判断不一致；
- 竞品图片、行业图片和用户内容难以统一筛选；
- 研究参考图未经确认就可能进入最终方案。

### 3.4 项目管理痛点

- 历史项目、原始文件、确认文件和规则版本难以追溯；
- 重新分析容易覆盖旧结果；
- 用户离开页面后无法确认任务进度；
- 结果需要再次整理成可交付的视觉看板和 PDF。

## 4. 核心用户旅程

```text
创建项目
  -> 填写项目名称
  -> 上传 Markdown、Excel 和图片
  -> 选择或新增规则 Skill
  -> 启动产品理解
  -> 编辑并确认产品事实和卖点证据
  -> 启动市场分析
  -> 查看 Markdown 和联网调研
  -> 调整资料权重
  -> 确认图片候选或上传补充图片
  -> 启动视觉策划
  -> 查看交互式视觉看板
  -> 编辑文字、图片和顺序
  -> 导出视觉看板 PDF 和图片 ZIP
```

### 4.1 用户控制原则

- 每个阶段由用户手动启动；
- 阶段不会自动跳转；
- 产品事实和卖点证据必须确认后才能进入市场分析；
- 图片候选必须经过弹窗确认后才能进入视觉策划；
- 用户可以取消任务；
- 用户可以离开页面后再次查看进度和结果。

## 5. 产品信息优先级

### 5.1 Markdown 优先

- Markdown 是产品资料和卖点优先级的最高来源；
- Markdown 中已有的卖点顺序直接展示；
- 联网数据不得重新排序或覆盖 Markdown 卖点；
- 联网数据用于补充、验证和发现机会点；
- 默认来源权重为 Markdown `8`、联网检索 `2`；
- 权重可以在第二页编辑，应用后重新计算展示结果。

### 5.2 信息类型

页面和输出需要区分：

- 事实：资料或网页直接存在的信息；
- 推断：基于多个事实得到的判断；
- 假设：资料不足时暂时采用的前提；
- 设计建议：用于视觉执行的方案建议。

## 6. 页面和功能

## 6.1 第一页：产品需求输入

### 目标

作为总控制台，完成项目创建、资料上传、规则选择和第一阶段启动。

### 功能

- 用户自定义项目名称；
- 上传 Markdown；
- 上传图片；
- 上传 Excel；
- Excel 自动转换为 Markdown；
- 保存原始 Excel 和转换后的 Markdown；
- 查看当前项目文件列表；
- 查看当前项目版本号；
- 按类型选择规则 Skill；
- 上传新的规则 Skill；
- 启动产品理解；
- 查看历史项目。

### 规则 Skill 类型

每个项目每种类型只启用一条规则：

- 产品事实校验规则；
- 图片搜索规则；
- 视觉策划规则。

当前规则和历史规则分开显示。旧规则不出现在当前选择列表中，但历史项目可以查看当时使用的规则原文。

## 6.2 第二页：规则校验与设计调研

### 目标

完成产品事实确认、卖点证据确认、市场资料展示、联网调研补充、权重调整和图片候选确认。

### 内容区域

- 阶段状态和进度；
- 产品事实 Tab；
- 卖点证据 Tab；
- 设计调研 Tab；
- Markdown 原始资料；
- 联网调研补充；
- 当前权重；
- 图片候选确认入口。

### 产品事实

展示和编辑：

- 产品基本信息；
- 品类；
- 面料成分；
- 版型；
- 功能；
- 核心卖点；
- 目标人群；
- 使用场景；
- 用户痛点；
- 尺码信息；
- 产品限制和不确定信息。

用户确认后，当前产品事实成为市场分析的正式输入。

### 卖点证据

展示：

- 卖点名称；
- Markdown 原始顺序；
- 产品视角；
- 用户视角；
- 证据或图示参考；
- 来源文件；
- 信息类型标签。

### 资料权重

默认显示：

```text
Markdown 资料权重  8
联网检索权重        2
```

用户修改权重后点击「应用权重」，系统重新计算：

- 文字结论排序；
- 证据强度；
- 图片候选推荐排序。

两个权重总和固定为 `10`，权重保存到项目版本。

### 图片候选确认

图片候选通过弹窗确认，不直接铺满页面。

弹窗支持：

- 图片大图预览；
- 分类筛选；
- 采用；
- 弃用；
- 待定；
- 批量操作；
- 查看来源链接；
- 查看搜索词、关联卖点和 AI 推荐理由；
- 用户直接上传补充图片。

只有用户标记为「采用」的图片进入视觉策划。

## 6.3 第三页：视觉看板

### 目标

将已确认的产品事实、市场资料和图片参考转化为可交互预览，并在导出前允许有限编辑。

### 看板能力

- 模块查看；
- Tab 切换；
- 图片预览；
- 来源查看；
- 信息类型查看；
- 数据不足提示；
- 项目版本切换；
- 权重结果查看；
- 导出前编辑。

具体模块数量、顺序、图片数量和陈列方式由视觉策划 Skill 定义。

### 导出前编辑

允许编辑：

- 标题；
- 文字内容；
- 场景描述；
- 图片选择；
- 图片顺序；
- 模块顺序。

不允许修改视觉策划 Skill 定义的整体页面结构和来源证据记录。

### 导出

支持：

- 导出视觉看板 PDF；
- 导出视觉看板用到的图片 ZIP。

PDF 只包含第三页视觉看板正式内容，不包含 SaaS 动态提示。图片 ZIP 用于保存当前导出看板使用的图片。

## 7. MVP 功能列表

### P0：必须实现

- 本地网页应用；
- 单个项目创建；
- 自定义项目名称；
- Markdown、Excel、图片上传；
- Excel 转 Markdown；
- 原始文件和转换文件保存；
- 规则 Skill 按类型保存和选择；
- 产品事实表生成；
- 卖点证据表生成；
- 产品事实在线编辑和确认；
- Markdown 资料展示；
- 联网调研 Skill 插口；
- 图片候选弹窗确认；
- 用户补充图片上传；
- Markdown/联网权重编辑；
- 三阶段手动启动；
- 进度条和任务状态；
- 取消任务；
- 交互式视觉看板；
- 导出前编辑；
- PDF 导出；
- 图片 ZIP 导出；
- 项目版本和历史查看；
- 来源、截图和规则版本保存。

### P1：后续实现

- 服务器部署；
- 团队协作；
- 登录和权限；
- 更丰富的图片筛选；
- 自动评估和 Skill 迭代建议管理；
- 更复杂的视觉看板模块。

## 8. 功能黑名单

第一版不得实现或不得默认引入：

- 用户登录和权限管理；
- 团队服务器部署；
- Figma 式自由画布；
- 任意拖拽页面结构；
- 规则 Skill 上传时的内容格式校验；
- 固定写死 Google、Amazon 或竞品独立站的搜索方法；
- 将研究图片默认作为商业发布素材；
- 用联网数据覆盖 Markdown 卖点顺序；
- 未确认图片进入视觉策划；
- 通过前端状态代替项目和版本持久化；
- PDF 中展示证据链接、技术状态、权重或调试信息；
- 任务取消后继续展示本次运行中的中间结果。

## 9. 非功能要求

- 用户可以离开页面后重新查看任务进度；
- 失败时显示原因，规则执行失败自动重新执行；
- 单个联网来源失败不阻断其他资料处理；
- 数据不足必须明确标记，不得编造；
- 原始文件、确认文件和历史版本不能被覆盖；
- 任务、项目和规则状态清晰可追溯；
- 页面不能出现文字重叠、图片溢出和布局跳动。

## 10. PRD 验收标准

### 项目和文件

- 可以创建自定义名称项目；
- 可以上传 Markdown、Excel 和图片；
- Excel 自动转换为 Markdown；
- 原始 Excel 和转换 Markdown 都被保存；
- 可以查看当前项目文件。

### 流程和人工确认

- 三阶段按顺序执行；
- 每阶段由用户手动启动；
- 产品事实和卖点证据确认后才能进入第二阶段；
- 图片候选必须在弹窗中确认；
- 只有采用图片进入第三阶段；
- 用户可以取消任务并重新进入项目查看状态。

### 结果和导出

- Markdown 卖点顺序不会被自动改变；
- 权重修改后结果会重新展示；
- 第三页支持交互预览；
- 导出前可编辑指定内容；
- PDF 只包含视觉看板；
- 图片 ZIP 包含当前视觉看板使用的图片；
- 旧版本可以切换查看。
