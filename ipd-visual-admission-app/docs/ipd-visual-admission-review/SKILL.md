# IPD 产品视觉准入审核

## 目的与边界

判断资料是否具备进入视觉制作的条件，不判断产品真实性或合法性的最终责任。产品、法务和平台合规仍对其职责范围内的事实负责。

每个对外卖点都必须形成闭环：

`产品主张 = 产品事实 + 适用范围 + 有效证据 + 真实展示方式 + 责任人`

不得为需求方创造产品事实；不得以视觉表现弥补证据缺失；不得把竞品资料或 VOC 当作本产品功能证据。

## 所需能力

- 上游已完成资料解析、分类和分块，并传入可定位的结构化资料块。
- 一个 LLM 调用能力：每次调用只处理一个任务包，并要求 JSON 输出。

读取 [审核规则](references/audit-rules.md) 和 [处理协议](references/processing-contract.md) 后执行。LLM 提示词和报告契约见 [任务模板](references/llm-task-templates.md)；验收样例见 [评估案例](references/evaluation-cases.md)。

## 输入

- `document_index`：上游预处理输出的资料目录，包含资料类型、字段、来源定位和块 ID。
- `content_chunks`：上游预处理输出的结构化资料块。
- `review_id`：本次审核唯一标识。
- `product_scope`：已知的型号、SKU 或版本；未知时传 `null`。
- `owner`：卖点、资料或审核责任人的已知信息；未知时传 `null`。

只把与当前规则有关的资料块、上游阶段 JSON 和最小元数据送入 LLM。不得将完整 Excel、图片二进制、完整历史对话或其他阶段的原始片段重复注入。

## 执行顺序

1. 读取上游提供的 `document_index`，按 [资料优先级与召回](references/audit-rules.md#1-资料优先级与召回) 确认营销资料对接包、产品说明书和其他资料的位置。
2. 对每个资料模块仅调用一次“资料定位” LLM；返回资料类型、字段映射、来源定位、置信度和缺失项。
3. 先执行一票退回检查。只对型号/SKU/版本、核心卖点证据、跨资料的成分/参数/尺码/功能矛盾发起独立 LLM 调用；任一项确认命中即最终状态为 `不通过`，但仍完成所有检查并列出整改项。
4. 分别对营销资料对接包和产品说明书进行“只看字段是否填写”的完整度检查。不得在该阶段判断内容好坏。按规则计算原始分、可审计满分和换算百分制。
5. 将 USP、VOC、产品说明书、RTB/质检报告、基础卖点、场景、Slogan 分为最小任务包，逐条进行第二步输入信息排查。一个 LLM 调用只执行一种规则，并只带该规则必要的片段。
6. 对每条基础卖点调用“展示方案”任务，生成可真实拍摄/制作的展示建议；无法被可靠展示时标为 `展示困难`，不是凭空补证。
7. 用汇总器只合并各任务的 JSON 结论、证据定位和短摘要，生成最终报告。汇总器不得重新阅读原始资料块，也不得推翻已确认的一票退回结论。

## 分块约束

- 输入资料块由上游预处理提供；本 Skill 不规定或执行 Excel 解析、表头识别和分块方式。
- 一个 LLM 调用只执行一个审核规则，只读取完成该规则必需的资料块。禁止把同一产品的全部资料块合并后再调用。
- 各阶段只传递 `claim_id`、证据定位、结论、风险和不超过 120 字摘要；需要回看时向上游请求对应资料块。
- 同一事实出现于多表时保存各来源定位，不做静默覆盖。冲突判断必须基于至少两处可定位的原文。

## 结论规则

- `不通过`：命中任一一票退回事项。
- `有条件通过`：未命中退回项，但存在关键卖点证据缺失、功能验证/质检缺失、关键展示困难、结论超证据或 Slogan 不可直观感知等高风险项。
- `通过`：未命中退回项，完整度和所有输入检查均无高风险缺口。不得仅因完整度高而判定通过。
- `待人工确认`：解析失败、来源无法定位、冲突无法可靠判定，或产品范围/责任人信息无法从资料中确认。

报告须区分“资料事实”“审核推断”“视觉建议”，不得把视觉建议写成产品事实。

## 输出

输出符合 [报告 Schema](references/report-schema.json) 的 JSON，并生成对应 Markdown 报告。主报告必须包括：

- 准入结论和一票退回结果；
- 资料召回路径和来源定位；
- 完整度评分报告；
- USP-VOC 关联短报（不超过 200 个中文字符）；
- 每条卖点的证据、功能验证、展示建议、超证据判断；
- 场景稀释、Slogan 可感知性、USP-关键流量词关联性；
- 待补资料、责任人和可复核定位。

JSON 使用机器状态码：`approved`、`conditional_approval`、`rejected`、`manual_review`；Markdown 分别显示为“通过”“有条件通过”“不通过”“待人工确认”。

## 失败处理

- 上游资料中没有营销资料时，按“营销资料缺失 -> 产品说明书 -> 其他资料”的路径继续，并在报告中记录路径。
- 营销资料存在但字段无法映射时，不可跳过；标记为缺失并在完整度中计零。
- 模型输出不符合 JSON Schema 时，使用相同任务包重试一次；仍失败则标记 `LLM_OUTPUT_INVALID` 并转人工确认。
- 证据不足只允许输出“未证实/待补”，不得输出“虚假”“合规”或任何确定性产品结论。
