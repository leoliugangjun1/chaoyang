# 分块处理协议

## 阶段与输入边界

| 阶段 | 输入 | 单次 LLM 任务 | 输出 | 禁止 |
| --- | --- | --- | --- | --- |
| A 资料定位 | 上游资料目录、字段映射、少量资料块 | 找到资料模块与字段位置 | `source_index` | 判断卖点真实性 |
| B 退回检查 | 型号/SKU/版本、核心卖点、证据片段、同类字段的多源片段 | 一类退回规则 | `hard_fail_check` | 以未读取内容推断矛盾 |
| C 完整度 | 已定位字段与值状态 | 一个模块的字段非空检查 | `completeness_check` | 评价内容质量 |
| D 关联/证据 | 一个 USP 或卖点及必要关联片段 | 规则 1/2/4/7 之一 | `claim_check` | 给出展示方案 |
| E 视觉可展示 | 单条基础卖点、已确认事实和证据 | 规则 3 | `visualization_check` | 伪造证据或验证功能 |
| F 场景/Slogan | 单场景或单条 Slogan 与对应 USP | 规则 5 或 6 | `communication_check` | 重评全案 |
| G 汇总 | 所有阶段 JSON 摘要 | 生成最终结论 | `admission_report` | 重新读取原始资料块 |

## 通用片段格式

```json
{
  "source_id": "marketing-claim-001",
  "chunk_id": "chunk-018",
  "headers": ["模块", "卖点", "证据"],
  "rows": [{"row": 12, "cells": {"模块": "USP", "卖点": "..."}}]
}
```

每项结论必须返回 `source_refs`；不能定位则用 `[]`，并将 `confidence` 设为 `low`。不得构造来源定位、文件名、报告编号或检测结论。

## 跨块关联

1. 在 A 阶段为卖点、证据、场景、Slogan、流量词创建稳定 ID，例如 `claim-001`、`evidence-003`。
2. 后续任务只传 ID、相关片段和必要的前序结论，不传全量资料。
3. 遇到同一 ID 的资料被拆到多个块时，先以确定性程序按 ID 聚合，再将聚合后的最小片段送入 LLM。
4. 跨资料矛盾使用同一规范字段比较：成分、参数、尺码、功能。原文不一致但单位/同义词可能等价时，输出 `needs_normalization`，交由确定性单位归一化或人工确认，不能直接判矛盾。

## 证据分级

| 等级 | 可用性 |
| --- | --- |
| A：本产品检测/质检/专业报告，可定位 | 可支撑报告范围内的功能结论 |
| B：本产品说明书、规格表、实物测量或可定位实拍 | 可支撑参数、结构和可见事实 |
| C：产品营销资料的未验证描述 | 可作为主张线索，不能独立证明核心功能 |
| D：VOC、竞品资料、行业常识 | 仅可支撑市场相关性，不可作为本产品证据 |

## 阈值与判定

- 对型号/SKU/版本：缺失明确字段且其他资料不能唯一识别产品，`hard_fail=true`。
- 对核心卖点：只有 C/D 级证据，或无证据，`hard_fail=true`。
- 对跨资料冲突：两个或以上可定位来源的规范化值不相等，且均指向同一产品范围，`hard_fail=true`。
- 无法确定产品范围、字段归属或证据适用范围：`manual_review=true`，不得自动通过。
