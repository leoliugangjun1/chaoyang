# 评估案例

## 案例 1：常规通过

输入包含唯一 SKU `LP-001-V2`；USP “6.5cm 加宽腰头”有产品规格表、实物量测图和对应证据行；VOC 反映用户关注卷边；说明书中有成分、尺码、使用说明和检测报告编号。各资料的参数一致。

预期：不触发一票退回；USP-VOC 报告说明 VOC 支撑相关性但不是功能证据；展示方案包含腰头量测和实物结构特写；最终状态可以是“通过”或因非关键资料缺失为“有条件通过”，不得把 VOC 记作产品检测证据。

## 案例 2：核心卖点只有 VOC

输入 USP “全天提臀不滑落”，VOC 有用户期待和竞品抱怨，营销表有该文案；产品说明书没有提臀/防滑验证，未提供质检报告。

预期：规则 `core_claim_evidence` 命中一票退回；功能验证检查也应失败；结论为“不通过”。不得因 VOC 与卖点匹配而放行，展示方案只能要求补测或降级，不能输出视觉补救。

## 案例 3：跨资料参数冲突与长表拆分

同一 SKU 的营销资料填写锦纶 80%，说明书填写锦纶 70%；卖点有 30 条，证据分散在多个上游资料块。

预期：按卖点和证据编号拆成多个任务包；汇总器只读取 JSON 摘要；规范化后确认成分不同，触发 `cross_document_conflict` 一票退回；最终“不通过”，报告可定位两处原文。

## 最小验收

1. 用案例 1 验证完整度、展示方案和证据分级没有混淆。
2. 用案例 2 验证 VOC 不能充当产品证据，且一票退回不会被高完整度覆盖。
3. 用案例 3 验证超过单包限制时会分块，并能保留跨表矛盾的来源定位。
