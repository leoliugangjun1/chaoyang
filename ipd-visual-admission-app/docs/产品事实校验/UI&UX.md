# IPD 产品视觉准入审核智能体视觉设计系统

## 1. 文档定位

本文档定义 IPD 产品视觉准入审核工具的页面信息架构、组件、状态、视觉 Token、交互规则和验收标准。界面服务于内部审核人员的快速判断、证据复核和问题分派，不是营销落地页。

## 2. 整体气质

安静、克制、可扫描、证据优先。页面首先让审核人员判断状态和阻断项，再进入评分、问题、来源和行动。

信息优先级固定为：最终准入状态、一票退回项、最高优先级问题和责任角色、完整度评分及缺失字段、证据等级和来源定位、其他风险和视觉建议。

## 3. 页面信息架构

### 3.1 审核任务输入页

包含项目名称、Excel 上传、文件信息、Skill 版本选择和启动审核操作。

### 3.2 任务进度页

包含任务状态、阶段进度、阶段摘要、错误信息、取消操作和人工复核提示。

### 3.3 准入报告页

包含报告元信息、状态总览、一票退回、完整度、USP-VOC 摘要、问题明细、来源定位和导出操作。

## 4. 色彩系统

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--color-canvas` | `#F4F5F2` | 页面背景 |
| `--color-surface` | `#FFFFFF` | 内容区 |
| `--color-ink` | `#171B1A` | 标题和正文 |
| `--color-muted` | `#68716E` | 辅助信息 |
| `--color-line` | `#DDE3DF` | 分隔线和边框 |
| `--color-dark-panel` | `#202624` | JSON 或证据摘要 |
| `--color-panel-text` | `#F5F7F4` | 深色面板文字 |

准入状态：

| 状态 | 色值 | 文案 |
| --- | --- | --- |
| `approved` | `#2F7658` | 通过 |
| `conditional_approval` | `#A8742A` | 有条件通过 |
| `rejected` | `#B44943` | 不通过 |
| `manual_review` | `#9A6D47` | 待人工确认 |

问题状态 `pass`、`feasible` 为通过，`risk`、`difficult` 为风险，`fail`、`not_feasible` 为失败，`uncertain` 为待复核。状态必须同时使用文字、图标和颜色。

## 5. 字体系统

中文优先使用 `Noto Sans SC`、`PingFang SC` 或 `Microsoft YaHei`；英文和数字优先使用 `Inter`、`Helvetica Neue` 或 `Arial`。

| 层级 | 建议字号 | 用途 |
| --- | --- | --- |
| 报告标题 | `28px - 36px` | 报告页标题 |
| 准入状态 | `24px - 32px` | 总状态 |
| 区域标题 | `18px - 22px` | 完整度、阻断项、问题明细 |
| 正文 | `14px - 16px` | 结论和行动 |
| 辅助信息 | `12px - 13px` | 来源、版本、时间 |

不使用负字间距；中文、英文和数字在可见正文中按可读性留白。

## 6. 页面布局

### 6.1 全局框架

```text
┌──────────────────────────────────────────────────────────┐
│ 项目名称 / 审核任务 / Skill 版本          刷新 / 导出      │
├───────────────┬──────────────────────────────────────────┤
│ 项目与任务导航 │ 当前页面内容                             │
│ 文件与规则     │                                          │
│ 任务状态       │                                          │
└───────────────┴──────────────────────────────────────────┘
```

桌面端使用窄侧栏加主内容区；报告页主内容最大宽度建议为 `1440px`。

### 6.2 报告页首屏

首屏依次展示报告编号和规则版本、准入状态、一票退回数量、完整度百分比、待人工复核数量和最高优先级问题。

```text
报告编号 / Skill 版本 / 原始文件
┌──────────────────────────────────────────────────────────┐
│ 不通过             一票退回 2   完整度 98.2%   待复核 1   │
│ 最高优先级问题：核心卖点缺少本产品检测证据                │
└──────────────────────────────────────────────────────────┘
```

### 6.3 完整度区域

并列展示营销资料 `marketing_score / 80`、说明书 `manual_score / 15`、原始总分 `raw_score / 95`、`audited_completeness_percent` 和 `unreviewed_weight`。缺失字段使用列表，不使用模糊的「资料不完整」。

## 7. 核心组件

### 7.1 AdmissionStatusBadge

显示机器状态和中文文案，包含图标。`rejected` 使用阻断图标，`manual_review` 使用人工复核图标。

### 7.2 HardFailPanel

按 `hard_fail_checks` 展示规则编号、状态、结论和来源。命中项置于报告上方，并提供跳转到问题明细的入口。

### 7.3 CompletenessPanel

展示评分计算和缺失字段。分数来自报告 JSON，前端不得重新计算最终准入状态。

### 7.4 FindingsTable

桌面端使用表格，列包含类别、状态、问题、必需动作、责任角色和来源数量。支持按状态、类别和责任角色筛选。长文本默认折叠，展开后显示事实、推断、证据等级、来源和行动。

### 7.5 SourceReferenceDrawer

点击 `source_path` 或 `source_refs` 打开来源抽屉，显示文件名、工作表、范围、行列、单元格和块 ID。无法解析的引用保留原始文本并显示「无法进一步定位」，不得补造路径。

### 7.6 ReportToolbar

提供刷新报告、复制 `review_id`、导出 JSON 和导出 Markdown。按钮名称表达动作，图标提供悬停提示。

## 8. 任务状态

上传状态包括初始、拖拽中、上传中、解析中、解析完成和解析失败。审核状态依次显示待启动、排队中、解析中、一票退回检查中、完整度检查中、卖点检查中、展示方案检查中、场景/Slogan 检查中、汇总中、已完成、失败、已取消和待人工复核。

进度条反映真实阶段，不使用无限旋转替代进度信息。

人工复核提示必须列出无法确认的产品范围、无法定位的来源、解析或字段映射失败、LLM 输出无法通过 Schema 的原因。

## 9. 交互规则

- 任务启动、取消和导出提供即时反馈。
- 取消后不显示当前运行的临时结果作为正式报告。
- 报告加载失败时提供重试按钮和可读错误。
- 来源抽屉关闭后保留筛选条件和展开行。
- 筛选为空时显示当前筛选条件和清空筛选操作。
- 不把 Prompt、原始对话、LLM 调试日志和内部重试信息放入正式报告页。
- 不在前端编辑 `admission_status`、`hard_fail_checks` 或报告事实。

## 10. 响应式设计

- 桌面端使用侧栏加主内容区，问题表可横向阅读但不压缩关键字段。
- 平板端侧栏可折叠，完整度指标改为两列。
- 移动端将主状态和阻断项置顶，问题表转换为纵向问题卡片，来源以底部抽屉显示。
- 长文件名、规则名称、报告编号和来源引用使用换行或省略，不能溢出。
- 固定报告指标区域尺寸，避免状态切换造成布局跳动。

## 11. 卡片和表格风格

普通信息区域使用白底、`1px` 边框和不超过 `8px` 的圆角。卡片只用于重复信息项、单条问题、来源对象和对话框。页面区域不做成单一巨大卡片，禁止卡片嵌套卡片。问题明细优先使用开放表格布局。原始 JSON 使用深色面板，但不作为主要报告内容。

## 12. 可访问性

- 状态文字和图标同时呈现。
- 所有图标按钮提供 `aria-label` 和悬停提示。
- 表格展开、筛选、抽屉和导出支持键盘访问。
- 正文和状态标签满足可读对比度。
- 错误信息与输入控件建立关联。

## 13. 需要避免的问题

### 13.1 视觉层面

不使用大面积渐变、装饰性光晕、漂浮圆球、无关插画、营销式 Hero 标题或单一紫色系主导页面。

### 13.2 信息层面

不隐藏一票退回项，不把 VOC、竞品资料和行业常识显示为本产品功能证据，不将推断、视觉建议和事实混在同一标签中，不显示无法验证的确定性结论。

### 13.3 交互层面

不让筛选、展开或抽屉导致页面跳动，不让长文本撑破表格，不在任务取消后继续显示旧任务临时进度，不使用不可关闭的弹窗阻断报告浏览。

## 14. 动效建议

页面切换使用 `160ms - 220ms` 淡入；任务阶段变化使用短暂进度过渡；完成提示使用一次性轻微强调；抽屉使用短距离滑入，关闭后保留页面位置。

## 15. Vibe Coding 实现要求

1. 先定义状态色、字号、间距和圆角 Token。
2. 先实现报告数据类型和状态映射，再实现组件。
3. 先实现首屏结论、阻断项和完整度，再实现明细筛选。
4. 使用真实长文本、多个来源引用和四种准入状态测试布局。
5. 使用 `report-schema.json` 作为页面字段校验依据。
6. 页面只渲染后端报告，不重新计算业务结论。

## 16. UI 验收标准

- 四种准入状态均有明确视觉差异。
- 拒绝状态和一票退回项在首屏可见。
- 完整度数值与报告 JSON 一致。
- `findings` 支持筛选、展开和来源查看。
- 来源缺失时显示无法定位，不伪造文件名、工作表或单元格。
- 证据等级、事实、推断和视觉建议可区分。
- 长文本、长来源和长文件名不会溢出或覆盖其他内容。
- 移动端不出现不可用的横向布局。
- 正式报告页面不展示 Prompt、调试信息和原始对话。
