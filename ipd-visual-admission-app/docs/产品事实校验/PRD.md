# IPD 产品视觉准入审核智能体 PRD

## 1. 文档定位

本文档定义 IPD 产品视觉准入审核智能体的产品目标、用户流程、业务规则、功能范围、报告内容和验收标准。产品依据固定 Excel 资料和已发布 Skill，输出是否具备进入视觉制作条件的审核结果。

产品不承担产品真实性、法律合规和质量认证的最终责任。涉及检测、质量和合规的事实必须引用可定位的原始证据并由对应责任角色负责。

## 2. 产品定位

### 2.1 产品定位

面向内部产品、质量、研发、营销和视觉团队的资料准入审核工具。用户上传固定模板 Excel 后，系统先通过 `excel_parser` 预处理，再按 `ipd-visual-admission-review` Skill 分阶段调用 LLM，生成可追溯的准入报告。

### 2.2 核心价值

- 将人工审核规则固化为可版本化 Skill。
- 在大型表格中定位资料、字段、卖点和证据。
- 优先发现会直接退回的问题。
- 区分事实、推断、证据等级和视觉建议。
- 为每个问题提供来源、责任角色和必需动作。
- 保留原文件、规则版本、阶段结果和历史报告，支持复核。

### 2.3 目标用户

产品负责人、质量或研发人员、营销或 GTM 负责人、视觉负责人和审核人员。

## 3. 用户痛点

- 大型 Excel 包含多个工作表和长表，人工难以定位资料和证据。
- 营销话术、VOC、竞品资料和本产品检测报告容易被混为一谈。
- 同一产品的成分、参数、尺寸、功能或版本可能在不同表格中冲突。
- 自然语言结论无法定位原始单元格，也无法说明责任角色和下一步动作。
- 规则更新或资料替换后无法解释历史报告差异。

## 4. 核心用户旅程

1. 创建审核任务。
2. 上传固定格式 Excel。
3. 系统保存原始文件并执行 `excel_parser` 预处理。
4. 选择已发布的 `ipd-visual-admission-review` Skill 版本。
5. 启动异步审核任务。
6. 查看资料定位、解析进度和阶段状态。
7. 查看一票退回检查和完整度评分。
8. 查看逐条卖点、证据、展示方案、场景和 Slogan 检查。
9. 查看准入状态、阻断项、风险项、来源和责任角色。
10. 导出 JSON 或 Markdown 报告。

用户明确触发上传、规则选择、启动、取消和导出。系统不要求逐条确认已有结构化事实，仅在来源不清、范围冲突或输出无法验证时请求人工复核。

## 5. 资料优先级与评分

### 5.1 资料优先级

1. 产品营销资料对接包：`80%`。
2. 产品说明书：`15%`。
3. 其他资料：`5%`，本版本不评价其完整度。

查找顺序为营销资料包、产品说明书、其他资料。其他资料仅用于定位产品范围、责任人和一票退回线索。

### 5.2 完整度规则

完整度只判断字段是否存在、非空、可读和与所属条目关联，不判断内容质量、真实性或卖点成立性。

```text
raw_score = marketing_score + manual_score
audited_completeness_percent = round(raw_score / 95 * 100, 1)
unreviewed_weight = 5
```

## 6. 页面和功能

### 6.1 第一页：审核任务输入

目标：创建可复现的审核任务。

功能：新建项目、上传固定模板 `.xlsx`、显示文件元数据、选择已发布 Skill 版本、启动审核、取消上传和重新选择文件。文件类型、模板版本和大小错误必须给出具体原因和下一步动作。

### 6.2 第二页：任务进度和阶段结果

阶段顺序为：排队中、解析中、A 资料定位、B 一票退回、C 完整度、D 卖点与证据、E 展示方案、F 场景与 Slogan、G 报告汇总、完成/失败/取消/人工复核。

功能包括阶段进度、阶段摘要、取消任务、无效 JSON 重试状态、规则编号和错误码。页面不显示完整 Prompt。

### 6.3 第三页：准入报告

首屏显示 `review_id`、Skill 名称和版本、`admission_status`、一票退回数量、完整度百分比、待人工复核数量和最高优先级问题。

报告区域按 Schema 排列：`hard_fail_checks` 阻断检查；`completeness` 评分和缺失字段；`usp_voc_brief` 摘要；`findings` 问题、来源、必需动作和责任角色；`manual_review_reasons` 人工复核原因；`source_path` 和 `source_refs` 资料路径和定位。

## 7. 业务规则

### 7.1 一票退回

- `model_version`：没有明确型号、SKU 或版本，且其他资料无法唯一识别产品。
- `core_claim_evidence`：核心卖点没有本产品证据，或仅有竞品/VOC/营销话术。
- `cross_document_conflict`：至少两个可定位来源指向同一产品范围，但规范化后的成分、参数、尺寸或功能不一致。

任一规则确认命中，最终状态必须为 `rejected`。信息不足时为 `manual_review`，不能直接判定失败。

### 7.2 USP 与 VOC

每条 USP 必须检查是否能在 VOC、竞品 VOC 或横向对比中找到用户问题、竞品弱点或差异线索，但 VOC 只能证明市场相关性，不能证明本产品功能。

### 7.3 功能性卖点验证

每条功能性卖点必须在产品说明书中找到验证描述，并具有本产品质检、检测、专业报告或可追溯证据。营销话术、竞品资料、VOC 或图片不构成功能验证。

### 7.4 展示方案

每条基础卖点的展示方案必须包含真实对象、镜头或版式、辅助图示或测量、可支持结论和限制条件。不能通过视觉方案制造证据或伪造效果。

### 7.5 证据范围

结论的对象范围、强度、持续时间、因果关系和绝对化程度不得超过证据。超出时标记风险并给出降级表达方向，审核不直接改写对外文案。

### 7.6 场景、Slogan 与流量词

场景必须解释 USP 的目标人群、使用动机和功能条件，不能将核心卖点稀释为普通属性。Slogan 的核心承诺必须能由真实产品图、使用图、结构图、测量图或检测可视化直接感知。流量词必须描述 USP 中可展示、可证实的内容，扩大适用范围或承诺未验证功能时标记为风险。

## 8. 证据等级

| 等级 | 定义 | 可支持结论 |
| --- | --- | --- |
| A | 本产品检测、质检或专业报告 | 功能结论 |
| B | 本产品说明书、规格表、实测或可定位实拍 | 参数、结构和可视事实 |
| C | 本产品未验证的营销描述 | 仅作为主张线索 |
| D | VOC、竞品资料、行业常识 | 仅支持市场相关性 |
| `none` | 无证据 | 不支持确定性结论 |

## 9. 最终状态

- `approved`：检查完成且无高风险缺口。
- `conditional_approval`：无一票退回，但存在关键证据缺失、功能验证缺失、展示困难、超证据结论或高风险通信问题。
- `rejected`：任一一票退回规则确认命中。
- `manual_review`：解析失败、来源无法定位、产品范围无法确认或输出无法验证。

## 10. MVP 功能列表

### P0：必须实现

固定 Excel 解析、A-G 阶段异步执行、三项一票退回、完整度评分、四种状态、问题清单、来源定位、Schema 校验、JSON/Markdown 导出、任务取消、重试和人工复核。

### P1：后续实现

多模板配置、人工修正后重新审核、报告版本比较、批量审核、历史趋势和团队权限。

## 11. 功能黑名单

- 仅凭 VOC 判定本产品功能。
- 用图片或视觉方案补齐缺失证据。
- 把推断写成事实。
- 让汇总模型重新读取原始资料。
- 前端自行计算或覆盖 `admission_status`。
- 自动修改已发布 Skill。
- 因完整度高而覆盖一票退回。
- 无法定位时伪造来源路径或单元格。

## 12. 产品验收案例

### 案例 1：常规通过

输入包含唯一 SKU、USP 对应本产品规格和实测证据、VOC 相关性、说明书字段和可定位检测报告。预期不触发一票退回；VOC 不被当作功能证据；展示方案包含真实测量或结构特写；最终为 `approved` 或因非关键资料缺失为 `conditional_approval`。

### 案例 2：USP 只有 VOC

输入包含 USP、VOC 和营销话术，但缺少本产品检测或功能验证资料。预期 `core_claim_evidence` 命中；功能验证失败；最终为 `rejected`。不得因为 VOC 与卖点匹配而通过，也不得用视觉方案补救。

### 案例 3：跨资料参数冲突

同一 SKU 在营销资料和产品说明书中填入不同参数，卖点证据分散在多个长表块中。预期按卖点和证据 ID 拆分任务；汇总器只读阶段 JSON；规范化后确认参数不同，触发 `cross_document_conflict`；报告保留两个以上原文定位；最终为 `rejected`。

## 13. 非功能要求

- 大文件任务使用异步处理并显示阶段进度。
- 每次 LLM 调用只传入最小必要内容。
- 阶段结果可持久化、可重试、可追溯。
- 原始文件、Skill 版本和报告历史不可覆盖。
- 外部 LLM 调用记录模型、规则、任务包摘要、耗时和错误码。
- 报告可由保存的输入快照和规则版本复现。

## 14. PRD 验收标准

- 用户可以上传固定 Excel 并启动异步审核。
- A-G 阶段按固定顺序执行，进度和失败原因可见。
- 一票退回、完整度、证据等级和最终状态符合 V1.0 规则。
- 报告字段与 `report-schema.json` 一致。
- 每条问题可查看来源、必需动作和责任角色；无法定位时明确显示。
- 三组评估案例产生预期状态且不出现禁止结论。
- 任务取消、无效 JSON 重试和人工复核流程可验证。
